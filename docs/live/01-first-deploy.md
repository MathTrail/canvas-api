## Что нашёл прогон

1. **Новый аккаунт не может войти сразу.**
   - Задание входит аккаунтом, привязку которого apply этой же выкладки создал секундами раньше.
   - Исправлено в T12: задания `deploy` и `hosting` после входа ждут, пока аккаунт даст токен, — `just ci-identity-ready`, до 8 минут.
   - Во второй выкладке ожидание заняло одну попытку.
   - Роли, которые тот же apply выдаёт новому аккаунту, ожидание не покрывает — долг Д14 в RUN.md.
2. **Sink `_Default` менялся в каждом плане.**
   - Конфигурация просила `unique_writer_identity = false`. Провайдер 8.3.0 читает sink без идентичности как sink с уникальной и показывал `true → false` в каждом плане и apply.
   - У sink, чей бакет в его же проекте, идентичности не бывает (справочник Cloud Logging API, прочитан 2026-10-14).
   - Теперь в конфигурации `true`. Apply кнопки во второй выкладке ничего не менял.
3. **Адрес сервиса.** Выход `service_url` давал адрес со случайной частью. Теперь он даёт адрес по номеру проекта, и по нему идут smoke и ссылка окружения `prod`.
4. **Выпуск отката без номера релиза.** `hosting:clone` пишет выпуск типа `ROLLBACK` без сообщения. После отката верхние строки списка выпусков релиз не называют, его видно у строк `DEPLOY`. Дописано в `docs/self-hosting.md`.
5. **Повторная выкладка того же релиза даёт новый образ.**
   - `ci-image-push` собирает образ релиза заново при каждой выкладке, а время сборки в образе и время файла сервера в его слое меняют digest. Кнопка дала `canvas-api-00004-8mk` с другим digest, чем у `canvas-api-00003-bw6`, и тег `v0.1.4` переехал на новый образ.
   - Каждая такая выкладка занимает одно из пяти мест автоочистки `keep-recent`. Образ, на который нужен откат, может раньше времени выпасть из этих пяти, а через 30 дней его удалит `delete-old`.
   - Работающей ревизии это не вредит: она ссылается на образ по digest. Вредит откату на старую ревизию, если её образ уже удалён: экземпляр не поднимется. Повторная выкладка — это и возврат кнопкой, и «Re-run failed jobs». Долг Д15 в RUN.md.

## Как повторить

Развёртывание с нуля описывает `docs/self-hosting.md`: bootstrap, секреты, окружения, затем мерж в `main`.

```bash
gh run watch <прогон «Release and deploy»>           # выкладка после мержа
gh workflow run deploy.yml --repo MathTrail/canvas-api --ref main   # кнопка, во время выкладки — проверка очереди
gh run rerun <прогон> --failed                      # если упало задание выкладки
just usage 1d                                       # расход против бесплатного лимита
```

Чек-лист, откат и возврат — разделы «Первая выкладка: чек-лист» и «Откат и возврат» в `docs/self-hosting.md`, по порядку.
